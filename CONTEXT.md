# D12Canvas

A Blazor Razor-component library for an embeddable, local-first diagramming canvas — a Miro-like board of extensible, developer-registered components.

## Language

**Board**:
The full set of a canvas's persisted content — its component instances, groups, and edges — modeled as flat, independently-addressable entities rather than an owned tree, plus an `Asset` table the entities reference. Distinct from canvas chrome (not board content) and from transient view state like zoom/pan (not persisted).

**Component type**:
A registered kind of canvas content (e.g. "sticky note"), identified by a stable key and defined by a rendered component plus a props type.
_Avoid_: shape, node — not used anywhere in this codebase; "component" is the established term.

**Component instance**:
A placed occurrence of a component type on a board, with its own bounds and props value.

**Component container**:
The box a component instance is rendered in: it positions the instance at its `Bounds`, hosts the author's component as its content, and declares what is hittable. It has one rendering, and `Selection` alone decides whether its affordances appear. It binds no pointer event and loads no JavaScript; its one binding is focus on its tab stop, the route by which `Tab` traversal selects (ADR 0036). Used outside a `Board` it is a positioned box with content and nothing more, showing no affordances and answering no `Pointer gesture`, because classification carries an entity id and a container that is not board content has none (ADR 0035).
_Avoid_: edit mode — a retired second rendering with its own entry gesture, deleted because it never had a working way in and out at the same time (ADR 0035).

**Inline edit**:
Editing a component instance's content in place on the board, inside the author's own component. A component type opts in by implementing `IInlineEditable`, whose one member is a parameterless `BeginEdit()`; registration records whether the type implements it, so the canvas knows before any instance mounts. The canvas always starts the edit: a double-press on an addressable instance (on a member of an unentered group the first double-press enters the group and the second edits), `F2` on a focused one, palette placement by click, `Enter`, `Space` or drop, and adding an edge label by double-pressing the line; a double-press on an existing label edits it. `Quick create` by click or `Ctrl`+`Arrow` starts one too. Copies (paste, duplicate, `Alt`-drag) never start one, and neither does a locked instance or one shown as an `LOD placeholder`. Before the editor opens the canvas pans the least distance that shows the instance whole, never zooming, and a request the next render does not mount is dropped. Entry focuses the editor without scrolling the container and selects all of the existing text. The editor calls `CommitInlineEdit(InstanceId, before, after, returnFocus)` once at every edit end: an unchanged edit records nothing, and a changed one is its own history entry, separate from any creation before it. `Escape` commits and returns focus to the instance's tab stop, to the edge's stop for a label, or to the canvas when that stop is not on screen; blur commits and leaves focus where it went (ADR 0051). `ParentCanvas` and `InstanceId`, the two cascading values every registered component receives, are part of the registration contract. An edit that ends empty removes the instance when its type registers an `IsEmpty` predicate over its `Props`, which only an `IInlineEditable` type may declare; `Text` declares one that counts whitespace as empty, so every edge label has it, and `StickyNote` does not, so a cleared note stays. The rule runs at every edit end however the edit opened, and nowhere else. When nothing has changed `History` since the instance's creation (a palette placement, a `Quick create` with its edge, or a new edge label), the creation is retracted, so a placement abandoned empty leaves no entry; otherwise the removal (`ChangeEdgeLabelCommand` to null for a label) is one entry with the text change and any group repair, and one undo restores the text inside its group. After an `Escape` removal focus goes to the source of a retracted `Quick create`, selecting it, to the edge's stop for a label, and otherwise to the canvas with nothing selected (ADR 0062).
_Avoid_: edit mode — the retired container rendering above, which never edited content.

**Key**:
The stable string a component type is registered under, chosen independently of its .NET type name so persisted boards survive renames/refactors of the underlying class.
_Avoid_: using the CLR type name as identity.

**Props**:
A component type's own serializable business data (e.g. a sticky note's text and color) — distinct from its bounds. Opaque to the library, which reads only what an author *declares* about a property (`[PanelEditable]`, `[AssetReference]`) and never infers meaning from its name or type.
_Avoid_: parameters — Blazor's own term for a broader concept (includes callbacks, render fragments); "props" specifically means the serializable data payload.

**Bounds**:
A component instance's position and size, tracked uniformly across every component type independent of its props — what lets the canvas query "what's on screen" without knowing any specific component type's shape. Always the *committed* value: it is never written while a `Pointer gesture` is in flight, which is what lets a `Command` read its own before-value straight off the field; what is on screen mid-gesture comes from `Live geometry` instead.

**Entity**:
Any board-content item addressable by a stable GUID assigned at creation — a component instance, a group, or an edge. Entities reference each other only by ID, never by direct ownership, so board content stays flat and independently mergeable. An `Asset` is not one: its id is derived rather than assigned, and nothing on a board points at it except a props field.
_Avoid_: node, object — ambiguous with terms already avoided for component instance.

**Asset**:
A piece of binary content held once on a `Board` — bytes, a mime type, and an id that is the SHA-256 of the bytes themselves. Deliberately **not** an `Entity`: it has no bounds, cannot be selected, hit-tested or grouped, and is referenced *by* entities rather than referencing them. Every entity id is a GUID *assigned* at creation; an asset id is *derived* from content, which is what makes the table add-only, dedupe for free, and merge idempotently. A `TProps` property opts in with `[AssetReference]` and holds `asset:<id>`; `DiagramCanvas` swaps that for a renderable `data:` URI before binding props, so a component author only ever sees an ordinary URL. Assets are collected when a board is serialised, never during a session, so undo can always bring deleted content back.
_Avoid_: image, file, blob — the seam carries any content type, and only the built-in `Image` component knows about images.

**Empty image**:
An `"image"` component instance whose `Url` is empty, rendered as the "No image" placeholder in the board's surface, border and muted-text tokens. A deliberate state, not a defect: palette placement produces one, and **Remove image**, in the property panel's `Url` row or the object menu, returns an image to it. It gets a picture from **Choose file…** in that row or **Choose image…** in the object menu, both shown only when every selected entity is an image and both filling every selected image as one history entry, or from a file dropped onto it: the first image file of a drop whose topmost instance is an empty image fills it, and every other file becomes a new instance cascading by `+20, +20` from the drop point, all in one history entry. A drop on anything else, a filled image included, and a pasted bitmap always make new instances, even with an empty image selected. Filling keeps the instance's box; a new instance takes the picture's pixel size in board units, scaled down to fit half the visible viewport and never up. The bytes enter only through `Board.AddAsset`, after the browser has decoded them and their type has been checked as a plain `image/*` subtype; nothing else a file carries, such as its name, crosses into .NET (ADR 0052).
_Avoid_: placeholder image, blank image.

**Group**:
A named collection of component instances and/or nested groups, treated as one movable/resizable unit. Membership is a reference list (`MemberIds`) held by the group, not a back-pointer on each member; a group's bounds are computed from its members on demand, not stored. Every member id resolves, and a group always has at least two members: a delete that leaves one dissolves the group and a delete that leaves none removes it (ADR 0053). The canvas and load guarantee this; a host calling `Board`'s mutators directly can break it. Layering commands (ADR 0008) applied to a group are bulk writes across member `ZIndex` values, preserving members' relative order — a group has no z-position field of its own.

**Selection**:
The transient, unpersisted set of entities currently chosen by the user. Held as **two parallel sets**, one of component instances and groups and one of edges, because an instance id, a group id and an edge id are all bare `Guid`s that only `Board` can tell apart, and because group expansion is meaningless for an entity that cannot be a group member. A command that cannot express an edge **skips** it rather than refusing the selection, which is ADR 0017's locked-entity rule applied again: delete and lock take both kinds, while align, distribute, z-order, group, resize and the arrow-key nudge read instances only, an edge widens no bounding box and counts toward no threshold, and grouping leaves a selected edge selected beside the new group. Shift+click on an edge toggles it without disturbing the rest. An edge joins a marquee by closure over what the marquee already selected rather than by any geometric test, and Select All (`Ctrl+A`) takes every top-level entity and every edge (ADR 0037). The host reads the two halves as `SelectedComponents`, which expands groups to their member instances, and `SelectedEdges`; `SelectionChanged` fires when either changes. Every selected id is a sibling at one level: top-level entities, or the direct members of the `Entered group` when one is entered (ADR 0044). Distinct from `Group`: selecting 2+ instances and invoking an explicit "group" action promotes that selection into a `Group`, but selection itself is never serialized, tracked in undo/redo, or part of `Board`.
_Avoid_: conflating with Group — a selection is ephemeral view state, a Group is persisted board content. _Avoid_ also: reading "the selection" as one collection — "is anything selected" is a two-part question by design.

**Entered group**:
The one `Group` the user has stepped inside, so that its direct members can be addressed. Transient view state beside `Selection`, never persisted and never in `History`, and not a tool mode. Entered one level at a time, by a double-press on a member (or on the selection box over a selected group, at the member under the pointer) or `Enter` on the group's tab stop, which hands focus to the first member's stop. Left one level at a time by Escape, which selects the group just left and, when the keyboard was on a stop inside, hands focus back to that group's stop. A primary or secondary press steps out as far as needed: on an entity until it is inside the entered group, on an edge all the way, and on empty canvas until the point lies inside the entered group's bounds, so a click or marquee inside the bounds stays in. Focus landing outside steps out the same way, and if an undo, delete or ungroup removes the entered group the scope falls back to the nearest group still in place. While a group is entered, the `Selection` holds only its direct members, the marquee sweeps only its contents, `Ctrl+A` selects its direct members, and `Ctrl+G` nests a new group inside it, unavailable when every direct member is selected; grouping and ungrouping inside a group rewrite the parent's member list in the same history entry. An entity is addressable when it is top-level or a direct member of the entered group; content in any other instance answers a press as the instance, through a marker C# renders that the press listener reads, so an author's control inside a group that is not entered does nothing until the group is. Only addressable instances and groups have tab stops, and the entered group's own stop gives way to its members'. Drawn as a dashed outline in `--d12-muted-text` round the innermost entered group (ADR 0044).
_Avoid_: focused group, group scope, edit mode, isolation mode.

**Additive traversal**:
The keyboard's way to build a multi-selection. `Space` on a focused tab stop adds it to the `Selection`, never removing it, and starts the mode. While it is on, `Tab` and `Shift+Tab` move focus without selecting, and `Space` toggles the focused stop, an instance, group or edge stop alike. Outside it, focus drives selection as ADR 0010 says. Transient, never persisted, not a tool mode. Ended by `Escape` (which keeps the selection, and is the stage after ending `Port placement` or port picking and before stepping out of the `Entered group`), a pointer press, focus leaving the canvas, `Enter` on a group stop, or a command that hands focus to a named target, such as `Ctrl+G` or click-to-add. Emptying the selection with `Space` does not end it, and port picking sits on top of it. A focused stop that is not selected draws a dashed accent outline, and the mode has no other indicator (ADR 0059). `Ctrl+Tab` has no binding: the browser takes it first.
_Avoid_: add mode, multi-select mode, focus mode.

**Directional focus**:
Moving focus to the nearest instance or group stop in an arrow's direction, by `Ctrl+Shift+Arrow`. A stop in the same row or column wins over a nearer one off it, and nothing in that direction means nothing happens. It measures from the focused stop, a focused edge from the stop its source resolves to, or from the selection's box when nothing is focused, or from the viewport centre when nothing is selected either. It reaches only the stops in the tab ring, so it never pans, never an edge, which stays one `Tab` after its source, and while a group is entered only that group's members. It does nothing while a press owns the board or a port is being picked. A focus move like `Tab`: it selects its target, except inside `Additive traversal`, where it moves focus only (ADR 0060).
_Avoid_: spatial navigation (the W3C CSS draft for browser-driven arrow navigation, with different rules), arrow navigation (plain arrows nudge), jump (implies panning).

**Edge**:
A connection between two endpoints, rendered per its own routing style and arrow settings. Each end is independently one of four shapes: a standard `Port`, a custom `Port`, an `Auto endpoint`, or a fixed board point that tracks nothing. An entity in its own right (`Board.Edges`), but its label — when present — is embedded on the edge rather than a separate entity, since a label has no existence independent of the edge that owns it. Its routing style is independent of what its ends attach to, in deliberate divergence from every reference tool (ADR 0027). The router still reads each end's side: `Orthogonal` leaves along it and routes around the two connected shapes, `Curved` bends out along it, and a floating end routes as if it faced the other end. The label sits halfway along the drawn path (ADR 0049). A full member of the `Selection` alongside component instances, with one asymmetry that follows from having no `Bounds`: a move translates its **floating** endpoints and never its attached ones, which track their component and have no stored coordinate to write. The moved ends ride the `Gesture preview` and commit as `ChangeEdgeEndpointCommand`s in the same history entry as the shapes (ADR 0037). A tab stop in reading order, placed directly after the stop its source resolves to, or at its source point when that end floats. It has no stop while a group is entered, because it is never a member of one (ADR 0054). Paints beneath every component instance by rule, in its own `Paint layer`, so it has no `ZIndex` and no arrangement commands: there is nothing to restack it against (ADR 0055).
_Avoid_: reading an edge as unmovable — an edge with both ends floating, which is what ADR 0009's palette creates, moves as a whole. _Avoid_ also: connector, link — "edge" is the established term (already anticipated in `Board`'s and `Entity`'s definitions before it had content of its own).

**Port**:
A named attachment point on a component instance that an edge can connect to, positioned as a fraction of the instance's bounds so it stays correct across resize. Every instance gets four standard ports (top/right/bottom/left, at border centers) automatically; an end user may add further custom ports to a specific instance at runtime — this is instance-scoped runtime state, not something a component type's developer declares at registration. A custom port can be removed, by the object menu's **Remove port** row on its span or by `Delete` or `Backspace` while port picking highlights it; every edge end pinned to it becomes an `Auto endpoint` on the same instance and the edge's other end is left alone. One removal is one history entry, a `RemoveCustomPortCommand` with one `ChangeEdgeEndpointCommand` per converted end, and its undo puts the port back at its index in the instance's list, which is the `Space` cycle's order and the saved order, and re-pins every end. Removal is unavailable on a locked instance or when any edge pinned to the port is locked. During port picking `Delete` acts only on a highlighted custom port: on a standard port or the auto stage it does nothing, so it never deletes the instance being picked on. After a removal the pick stays open on the auto stage, and a connector source armed on the removed port is disarmed. Standard ports cannot be removed (ADR 0061). An `Auto endpoint` chooses among the four standard ports only: a custom port is a deliberate placement and never catches an edge nobody aimed at. Drawn as a dot, but grabbed as a stretch of border: its `Hit region` is a span of the `Border partition`, so a connector is pulled from the side rather than aimed at the circle. Visible on a single `Selection` and on the one component under the pointer during a live connector drag, never on hover and never on a member of a multi-selection; the shape the drag starts from is never the one under the pointer that lights up, since a drop there changes nothing. Because a `Hit region` and its rendering leave together, **where a port is visible is also where an edge can be pinned rather than auto-attached**, and a port squeezed out of the partition draws no dot unless the keyboard pick highlights it (ADR 0028). A press on a port span carries an edge end only when that end is pinned to the port; an `Auto endpoint` names no port, so a press on the side it currently leaves from pulls a new edge instead. The dot is 20px at full size and stops shrinking below a quarter zoom, while its span keeps tracking the zoom.
_Avoid_: reading the dot as the target — the dot is the visual and the span is the region, and they are deliberately different sizes.

**Border partition**:
How one side of a component instance divides between connecting and resizing, computed per side in screen pixels. The side's **run** is its length minus a corner reserve at each end, so a corner handle is never on a side and two-axis resize can never be covered. Every `Port` on the run takes the stretch nearest to it, capped at the port target; ports closer together than that cap split the difference, and in a below-floor collision a standard port keeps its full width and the custom port is clipped. Resize takes what is left. Anything below the floor drops from render and hit together, so a crowded side can lose its resize spans entirely and a crowded cluster of ports can lose its custom members, both recoverable only by zooming in; a run shorter than the floor holds nothing at all. One number governs it — the port target, 24 screen pixels, defined in C# and published through `ContentStyle` as `--d12-port-target` — with the floor (half of it), the corner reserve and the corner target derived from it. Each span is placed as a fraction of its side plus a count of port targets over `--d12-scale`, and reaches half a port target outward and no further inward than halfway across the instance, as a corner target is narrowed to half a short side, so on a shape too thin for them no two regions meet. A selected instance shows its port spans, its resize spans and its four corner handles; the drop target of a connector drag shows its port spans alone. Never drawn: sides have no handle, and the partition is expressed entirely by the **cursor** — `crosshair` on a port span, `ns-resize` or `ew-resize` on a resize span, the diagonal cursors on corners, `move` on the body — one CSS declaration per span because a `Hit region` is already a real element. The corner handle's dot is 10px and, like a port's, stops shrinking below a quarter zoom (ADR 0028).
_Avoid_: port strip — that names the old full-length double-click target, which is now one kind of span among several, and whose double-click is gone: adding a custom port is a context-menu row only, since a plain click on a port span is now a `Quick create` (ADR 0030).

**Port placement**:
The keyboard's route to adding a custom `Port`, entered from the **Add port…** row of a keyboard-opened object menu on a single selected, unlocked instance with no edge selected, which also hands focus to that instance's tab stop. A hollow provisional port starts on the Top side a quarter of the way along, rounded to the nearest grid line under `Snap-to-grid`, and moves where each arrow points, kept on the border: an arrow along the side slides it, an arrow pointing into the shape crosses it to the opposite side at the same fraction, and an arrow pointing out of the shape does nothing. A slide stops at the corner; pressed on into the corner it turns onto the adjacent side at the same point and stops, so holding `Left` on the Top side ends at the top of the Left side. At a corner, an arrow along the adjacent side moves it down that side, so `Down` at the top-right corner goes down the Right side. Each press is one `Nudge` step measured along the side, the same rule as nudging the selection at the same zoom and snap state, and `Shift` moves ten. `Enter` adds it as one `AddCustomPortCommand`, one history entry whatever the number of slides, and leaves focus and selection on the instance, so the new port is in port picking's `Space` cycle at once. `Escape` ends placement without adding and keeps the selection; it is the stage beside port picking, so the next `Escape` goes on to the stages after it. `Tab`, a pointer press, focus leaving the canvas, or any other focus landing off the instance's stop ends it without adding; the menu handing focus back to the canvas before it reaches the stop does not. The provisional port is mode state on `DiagramCanvas`, not a `Gesture preview`: sliding writes nothing to `Board` or `History`, and while placing only the arrows, `Shift`+arrows, `Enter` and `Escape` act, every other key that writes `Board` or the `Selection` (`Delete`, `Space`, undo and redo, `Alt`+`Arrow`, `Ctrl`+`Arrow`, `Ctrl`+`Shift`+`Arrow`, `F2`, the menu keys, select all, group, z-order, lock, duplicate, cut and paste) doing nothing. Entering it ends a port pick in progress and keeps an armed connector source. Clipped and dropped positions are allowed, as they are for the pointer, and nothing is announced (ADR 0050).
_Avoid_: port picking — that is the `Enter` mode that chooses an existing port for a connection, and placement never connects anything.

**Auto endpoint**:
An edge end attached to a component instance without naming a `Port`, leaving the canvas to keep choosing one. It resolves to the standard port on whichever side an aiming line — from the instance's centre to the other end's own reference point — crosses, so the choice is re-made as either end moves and can never face away from what it connects to. The centre is only ever an aiming reference and never an attachment; the one case with no crossing, the other end being inside the rect, takes the nearest side instead. Produced by dropping a connector drag anywhere on a component's body rather than on a port, whether pulling a new edge or carrying an existing end, and by committing a keyboard port pick without naming a side. A drop resolves from what lies under the pointer, topmost first: a port pins, a body gives auto, nothing floats, and chrome or an edge label above is looked through. A drop on the component the other end is attached to does nothing, so an edge never joins a component to itself. Port picking starts on auto, shown by all four standard ports highlighted at once; `Space` steps on to `Top`, the other standard ports, then any custom port and back to auto, and the arrows still jump straight to a side. A press on the standard port an auto end currently resolves to carries that end, unless an end is pinned there. Because it consults the other end, resolution is pairwise — the one geometry on `Board` that cannot answer for a single endpoint alone, so `Board` and live geometry both resolve an edge's two ends together (ADR 0027). Saved as a component id with no port and no point, a combination nothing produced before, so it needed no new field and no schema bump, and a floating end that happens to sit inside a shape loads as floating.
_Avoid_: calling it floating — a floating end tracks nothing, where this one tracks everything.

**Quick create**:
Duplicating a selected instance beside itself and connecting the two, in one act. Carried by a plain click on a `Port` span — a `DragEdgeEnd` that releases before crossing the `Drag threshold`, so it adds no member to the `Pointer gesture` set — and by `Ctrl`+`Arrow`, which reaches the four standard ports only. What it makes is a true duplicate (same type, same props, same size as the source, not the registration's `DefaultSize`), placed at the source's border on the pressed side plus two grid cells, stepping further along that same axis while the slot is occupied. The new edge pins at the source port and takes an `Auto endpoint` at the target, so it re-chooses its side as either shape moves. The new instance takes `Selection` and focus and the source gives both up, which is what makes a chain chainable. One history entry (ADR 0030). A new instance of an editable type then opens for an `Inline edit` with its text selected, so typing replaces the duplicated label (ADR 0051). The copy goes through the duplication path, so its custom ports come too with fresh ids, and it starts no `Duplicate run`. The gap is two cells of the dominant grid whether or not snap is on; under snap the candidate box is snapped before it is tested, and the occupancy test counts a box that only touches another as occupied. A click on a port that an edge end is pinned to still quick-creates from it and leaves that edge alone. `Ctrl`+`Arrow` acts only on a single selected, unlocked instance with no edge selected, and does nothing while a press owns the board or while picking a port. An abandoned quick-created instance whose edit ends empty is retracted with its edge, and after `Escape` focus and selection go back to the source.
_Avoid_: reading it as placement — placement derives from a registration, this derives from an instance, which is why the two disagree about size.

**Interior edge**:
An edge both of whose endpoints resolve to component instances inside a given set of entities — the test for whether an edge belongs to that set rather than merely touching it. A **copy** carries the interior edges of the selected instances, a selected group's members counted recursively, plus every selected edge, and an end of a selected edge on an instance not copied becomes floating at the point it resolves to at the moment of the copy; an edge nobody selected with one end outside stays behind (ADR 0045). Cut removes exactly what the copy carried, so the interior edges go with the instances in the same history entry rather than being left pointing at nothing. The **marquee** takes an edge when every endpoint is either attached to a component the band selected, a swept group's members included, or floating inside the band (ADR 0037), which is a wider test than this one. **Paste** keeps an edge when every attached end resolves to an instance that materialised, so floating ends always pass and an edge that lost an endpoint to an unresolvable component type is dropped. The three readers differ, and they agree on a marquee's result because copy carries whatever is selected.

**Canvas chrome**:
UI anchored to a canvas's viewport rather than its pannable/zoomable board surface — it doesn't move when the board pans and isn't part of persisted board content. Two kinds, and the distinction is who places it. **Host-placed** chrome (`Palette`, `Minimap`, `PropertyPanel`) is a standalone component the host positions with its own CSS, wired to a canvas by reference, so `DiagramCanvas` never renders or positions it. The one thing it hands the canvas is a press: `Minimap`'s drag is a `Pointer gesture` the canvas owns. **Canvas-rendered** chrome (the context menu, the `Property bar`) is rendered by `DiagramCanvas` itself as a sibling of `.diagram-canvas`, positioned in plain container-relative pixels; it may derive that position from board geometry without becoming board content (ADR 0021). Host-placed chrome laid out *beside* the canvas shrinks the container the library measures, so placement stays correct for free; host-placed chrome *floated over* it occludes, and the library never learns that, so the host owns the consequence and compensates through the public `ZoomPanTracker` (ADR 0033).
_Avoid_: overlay, widget.

**Palette**:
The default canvas chrome component that lists registered component types for the user to pick from.

**Context menu**:
The canvas-rendered chrome a secondary press opens on release, one component with two content sets. The **object menu** opens when the press hit an entity and carries commands over the selection; the **canvas menu** opens on bare canvas, after the press has cleared the selection, and carries board and view settings. Both are composed from one list of sections in one fixed order, and each row decides its own eligibility from a menu context the canvas computes when the menu opens, so a section renders when any of its rows is eligible, a separator sits only between two rendered sections, and an unavailable row is hidden rather than disabled. Today the object menu is Cut, Copy, Paste, Duplicate; Delete; Group, Ungroup; the align strip and the four z-order rows; Lock or Unlock; Zoom to Selection, and the canvas menu is Paste; Select All, shown when the board has anything to select; Zoom to Fit, Zoom to 100%; Snap to Grid and Object Snapping, both checkbox rows carrying their state; Unlock All. Cut, Copy and Paste show only where the browser offers the clipboard to a click. Rows whose commands do not exist yet join the same list when they do. Placed once at the press point: it opens right and down, flips to open left or up of the anchor on whichever axis it would cross the container edge, and is clamped only when it fits on neither side. Its width, row height and separator are fixed by its stylesheet, so the canvas places it on the render that opens it without measuring it. It dies on the next press. A press inside `.diagram-container` only closes it: the press is stopped in the capture phase on `document`, before the canvas listener sees it, and the click or browser menu it would fire next is swallowed too. A press on the host's own markup outside the container closes it and still acts. Every key pressed inside the menu stays there, so Escape closes the menu and nothing more and the arrows rove between rows rather than nudging the selection; an Escape that reaches the canvas while a menu is open also only closes it. Unlike the persistent `Property bar`, which clamps instead of flipping, the menu is transient, which is why it flips (ADR 0023). Also opened by `Shift+F10` or the `ContextMenu` key, both on keydown and only on a canvas `Menu verdict`, where the content set splits on whether anything is selected rather than on what a press hit: the object menu draws at the bottom-left of the selection's on-screen box, kept inside the container, and the canvas menu at the viewport centre. A keyboard-opened menu focuses its first row, and when it closes focus returns to the element focused at the keydown, or to the canvas if a row removed that element (ADR 0026, ADR 0067). Add port here, last before the image rows, needs a side and a fraction, which only the stored press point carries, so it shows only when the opening press landed on a side's resize span or a standard port's span of the one selected, unlocked instance, and adds the port at the press point's fraction of that side in one history entry (ADR 0028). On a custom port's span **Remove port** takes its place, and shows only while removal is available, so a locked pinned edge leaves that span with neither row (ADR 0061). A keyboard-opened object menu on one selected, unlocked instance shows **Add port…** in its place, which starts `Port placement` (ADR 0050).
_Avoid_: right-click menu, popup menu.

**Minimap**:
The host-placed canvas chrome showing the whole board at a glance plus a rect marking the current viewport, so content that has been panned away from stays locatable. `Minimap` takes the canvas by reference, as `Palette` does, and fills whatever box the host gives it; the App floats it over the canvas's bottom-right corner. Renders one plain box per component instance, never a mounted component or an `LOD placeholder`, and never edges, so a board of only floating connectors shows a blank map. Maps the union of `Content extent` and the current viewport, so it shows both where content is and where the user is even when those no longer overlap. Holds its own `ZoomPanTracker`, sized to its own box, and reaches its scale through the same `Framing` computation the viewport commands use, 0.9 margin included. The boxes sit in board units under one transformed wrapper and render again only for a new `Board` or a change to its history, an undo included, so a pan moves one transform and redraws one rect; a gesture's preview never reaches them, and a moved shape's box settles at release. Navigation only: a click flies the viewport's centre to the pressed point as a framing flight, a drag keeps the viewport centred on the point under the pointer with no easing, and neither selects nor zooms. The drag is the `Pointer gesture` `MinimapPan`, owned by `DiagramCanvas` like the other seven and reported by the same pointer listener with classification off, so it takes capture, the drag threshold, Escape and a release outside the minimap like any other press; only the primary button presses it, and the press focuses the canvas so Escape reaches it. The map holds still while the press is held, so the point under the pointer cannot slide as the viewport moves, and settles on release; a drag past the mapped area can carry the rect off the map until then. Boxes take a muted tint of the minimap's own surface, since no registration carries an accent, and only the viewport rect uses `--d12-accent`. Declares the raised values and `color-scheme` on its own root (ADR 0064). Carries no keyboard route and is `aria-hidden` with no tab stop, decided rather than defaulted: framing chords and arrow-key pan already make navigation keyboard-complete, so it is a redundant view of state rather than a mouse-only control (ADR 0015, ADR 0026).

**Property panel**:
The host-placed canvas chrome that surfaces editable `TProps` fields for the current selection, built generically from each component type's declared editable properties rather than one bespoke panel per type. Holds the full schema, including everything with no `Property role` to put it in the `Property bar`. A component's `Text`-type content is excluded — edited inline/WYSIWYG on the canvas instead. Reads the *expanded* selection, so a selected `Group` is editable through its members (ADR 0021).

**Property bar**:
The canvas-rendered chrome that floats above the current selection carrying the properties judged by eye, drawn as glyphs with no text labels. Supplements the property panel rather than replacing it: the bar shows only properties declaring a `Property role`, the panel keeps the full schema. Anchored by transforming the selection's bounds into container pixels and clamping the result inside the container, sliding along an edge rather than flipping below. Hides for the duration of a pointer gesture and while a context menu is open (ADR 0021). While it has hover or focus, the rest of the selection chrome hides instead, outline included, so the change being made can be seen (ADR 0041).
_Avoid_: context toolbar, floating panel.

**Property role**:
The well-known role a property plays, drawn from a closed library-owned set (`Fill`, `Stroke`, `StrokeWidth`, `TextColour`, `FontSize`, `FontWeight`, `TextAlign`, plus four the library uses for an `Edge`). Declared explicitly by an author, never inferred — a glyph cannot be derived from a property's name or its `EditorKind`, since a rectangle's fill and stroke share a kind and a sticky note's `Color` is a background where a text instance's is a foreground. Each role declares the `EditorKind` and CLR type it expects and the label a merged row shows, so a mismatch is caught on the registration that causes it, and a type may declare each role at most once because the role is the merge key. Doing double duty: a role is both what admits a property to the `Property bar` and what merges it across types in a cross-type multi-selection (ADR 0021, replacing the free-string shared tag).

**Editable property**:
A `TProps` field exposed through the property panel, declared by default via an attribute on the `TProps` record and optionally overridden by the registration builder. Carries an `EditorKind` describing which panel control renders it, and optionally a `Property role`.

**EditorKind**:
The kind of control an editable property renders as in the property panel — a closed built-in set (Text, Color, Number, Checkbox, Dropdown, …) plus `Custom`, which takes an author-supplied `RenderFragment<CustomEditorContext>` (the property's current value plus a commit callback) for anything the built-ins can't express. A `Custom`-kind property can only be declared via the registration builder, never a `[PanelEditable]` attribute, since an attribute argument can't carry a RenderFragment.

**Mixed**:
A property row whose targets do not all hold an equal value. Decided per row, with `null` counting as a value and colours compared case-insensitively. A mixed row stays editable, and a commit writes the new value to every target. The `Property bar` and `Property panel` show it by one rule per `EditorKind`, and a `Custom` editor learns it from `CustomEditorContext.IsMixed` (ADR 0040).
_Avoid_: indeterminate, which is only the checkbox's rendering of it.

**Pointer gesture**:
The single behaviour that owns a pointer press, from `pointerdown` to release. Chosen once, at press, from the `Hit target` plus the buttons, modifiers and current `Selection`; its identity never changes mid-press, only its phase — `pointing` until the `Drag threshold` is crossed, `active` after, and `cancelled` once Escape or an interruption has ended its effects. A cancelled gesture keeps the pointer until its claiming button comes up, so the release reaches an owner and does nothing (ADR 0031). The exception is a window blur: that release happens in another application and never arrives, so a blur cancel also clears the gesture and releases capture (ADR 0066). Owned by one pointer *and one button*: only the claiming button's release ends it, and any other button going down or up meanwhile is dropped (ADR 0022). Only a primary press reads the `Hit target`'s role at all: a secondary or middle press is a `Pan` regardless of what it landed on — and on macOS a `Ctrl`+primary press *is* a secondary press, behind a platform check, because that is the system's own secondary click (ADR 0024). A closed set of eight (`Pan`, `MarqueeSelect`, `MoveSelection`, `ResizeSelection`, `DragEdgeEnd`, `SelectEdge`, `Native`, `MinimapPan`), all owned by `DiagramCanvas` — a `ComponentContainer` holds no gesture state at all, because a container is a box the pointer can leave and a gesture outlives the box. Held by pointer capture on a stable element so release is guaranteed wherever the pointer ends up (ADR 0018). Owns the board for the press as well as the pointer: in any phase, nothing but its own release writes `Board`, and the keyboard cannot change the `Selection`. A key that would do either does nothing, and the gesture carries on. A host replacing `Board` cancels it (ADR 0038). A modifier that chooses the gesture or the selection is read once, when it acts; one that changes what the running gesture does is read live, and a change with the pointer still arrives as a re-sent move (ADR 0043). The viewport stays live in every phase: the press point is anchored in board space, so whatever the pointer holds stays under it through a pan or zoom, a viewport change re-runs the tick and promotes a press still `pointing`, and during a `Pan` an outside viewport change re-anchors the pan so the two add (ADR 0056).
_Avoid_: confusing with `Gesture`, which is the *history* unit — four pointer gestures (`Pan`, `MarqueeSelect`, `SelectEdge`, `Native`) never produce one, and a `Gesture` can come from the keyboard or a paste with no pointer at all.

**Gesture**:
One completed user-facing action on the board — a drag from press to release, a resize, a prop edit committed on blur, a create, a delete, a group, an ungroup. The unit undo/redo operates on: a gesture becomes exactly one history entry, never one per intermediate frame. A `Pointer gesture` commits at most one of these, at release, in one place — never per intermediate frame, and never from the `pointing` phase.

**Wheel gesture**:
A run of wheel events bounded by a 300ms idle timeout, with `momentum === true` as an early terminator where the engine supplies one. Deliberately the *third* thing called a gesture here and the only one that touches neither of the others: it involves no press, so it is not a `Pointer gesture`, and it never produces a history entry, so it is not a `Gesture` — wheel zoom and pan stay out of undo entirely (ADR 0019). Its boundary exists solely to hold a `Wheel device profile` classification steady for the run. The canvas container's own non-passive wheel listener measures the run, since C# has no clock: it reads granularity from the run's first event, whole pixels or line deltas being coarse and fractional pixels fine, and hands C# each frame's summed deltas with that classification attached. A wheel gesture is live during a press too: the viewport change it makes re-runs the `Pointer gesture` that owns the press (ADR 0056).
_Avoid_: treating the idle timeout as an undo-granularity boundary. It was originally specified as one, that consumer no longer exists, and re-tuning it against undo would break classification stability instead.

**Wheel device profile**:
Which of `Auto`, `Mouse` or `Trackpad` a canvas is treating the wheel as coming from, naming one physical fact — **delta granularity**. A mouse notch arrives as a discrete 100px step, a trackpad fractional and fast. Decides three things together: whether a plain wheel zooms or pans, the ambient transform-transition duration (100ms against coarse input, 0ms against fine), and whether Shift binds to horizontal pan at all. `Auto` classifies at `Wheel gesture` start and holds for the run; `Mouse` and `Trackpad` pin it. `DiagramCanvas` takes it as the `WheelDeviceProfile` parameter, `Auto` by default. On both devices Ctrl or Cmd zooms, which is how a pinch arrives, and Alt pans both axes. Zoom multiplies the scale by `exp(-deltaY / 600)` about the pointer. The transition applies only to a wheel's own transform write, so a pointer pan or a keyboard command never eases. The host owns any control and any persistence — the library renders neither (ADR 0019); the App's board editor has a control bottom-left and does not persist the choice.
_Avoid_: reading `Auto` as a heuristic that merely correlates with the device. The integral-versus-fractional tell *is* granularity, and granularity *is* why the smoothing constant exists, so a misclassification still applies smoothing to exactly the input that needs it.

**Gesture preview**:
What the active `Pointer gesture` publishes while it runs, at press and then once per frame — `Bounds` overrides keyed by component instance id. The entities it overrides are that gesture's **participants**; `MoveSelection` publishes the whole selection at press, so they are known before the first move. ADR 0020 also gives it a pending edge line for a connector drag, ADR 0037 moved endpoints and ADR 0042 a pending fragment for a `Clone drag`; each arrives with the gesture that writes it. Provisional by definition: `Board` is never written mid-gesture, so cancelling is discarding it and committing is writing it back verbatim, leaving out every instance whose previewed bounds equal its committed ones. That is what makes a history entry record exactly what was on screen, and why a drag back to its start leaves no entry at all. Covers geometry only — a `Selection` replaced mid-gesture is restored from the `Selection snapshot` instead, not by discarding this (ADR 0020, ADR 0031).
_Avoid_: reading it as a cache of `Board` — only the owning gesture writes it, and it holds only what that gesture changes.

**Selection snapshot**:
The `Selection` as it stood the instant before a press, captured by `DiagramCanvas` for every `Pointer gesture` and restored if that gesture is cancelled. Both selection fields together, and now because both carry selection at once rather than because they are exclusive, which is the reason ADR 0031 gave and ADR 0037 removed. It exists because the `Gesture preview` covers geometry only, and because two things change the selection outside it: `MarqueeSelect` replaces it every tick, and a press on a non-member collapses it before any preview exists. Taken for every gesture rather than the ones that visibly need it, so a new gesture inherits it by position. The viewport deliberately has no equivalent — a pan is undone by panning back, where a selection has no route back at all, being excluded from `History` (ADR 0031).
_Avoid_: reading it as an undo step. It is consumed by cancellation and by nothing else; a committed gesture discards it untouched.

**Live geometry**:
The single read surface that turns board entities into their current board-space points and rectangles, consulting the `Gesture preview` before committed state. It exists to make one rule sayable: read `Bounds` off an entity when you mean committed state — a `Command`'s before-value, persistence — and go through live geometry when you mean what is on screen now. Endpoint resolution and a group's bounds each exist once on `Board`, taking where an instance's bounds come from as a parameter, with the committed entry point on `Board` and the live one here; instance placement, attached edges, the selection box and tab-stop order read the live ones. Windowed mounting and `Content extent` deliberately take the committed ones, and the `LOD placeholder` decision reads committed bounds and is frozen for a participant until its gesture releases. The viewport can move during any gesture, through the wheel and the viewport keys, so a gesture's participants have a sticky mount: anything mounted at press stays mounted, and a participant whose live bounds enter the viewport plus overscan mounts and stays until release; non-participants window normally (ADR 0056). A drag reaching the edge of the viewport still stops there rather than scrolling the canvas (ADR 0029). Internal to the library: a host asking `Board` a question means the committed answer.
_Avoid_: effective bounds — names one mechanism's single consumer rather than the question every reader is actually asking.

**Command**:
A recorded, invertible board mutation produced by a gesture — knows how to apply and undo itself. The set is `AddEntityCommand`, `RemoveEntityCommand`, `AddEdgeCommand`, `RemoveEdgeCommand`, `AddCustomPortCommand`, `RemoveCustomPortCommand`, `ChangeBoundsCommand`, `ChangeEdgeStyleCommand`, `ChangeEdgeLabelCommand`, `ChangeEdgeEndpointCommand`, `ChangeZIndexCommand`, `ChangeLockedCommand`, `MutateEntityCommand`, `NudgeCommand`, `ResizeStepCommand`, `GroupCommand`, `UngroupCommand` and `CompositeCommand`, which is every command in the code. Every command the canvas builds skips a `Locked` entity rather than failing, so a command over a mixed selection still acts on the rest; `ChangeLockedCommand` is the one that acts on a locked entity, since unlocking is how a lock ends, and grouping and ungrouping, which never touch a member, take locked members as they are.
_Note_: the guidance below was written when the set was smaller. Whether it is still meaningfully closed is an open question rather than a settled claim.
_Avoid_: inventing a new command type per feature — a generic primitive (especially `MutateEntityCommand` for opaque `Props`) should cover it first.

**History**:
The local, in-memory, session-scoped stack of `Command`s backing undo/redo for the current `Board` — capped at a fixed depth (a circular buffer), never persisted, and never tracked across a reload. Besides undo and redo it has one more operation, `Retract(command)`, which acts only while that command is still the top entry, by reference: it undoes it, drops it, leaves redo as it was and fires `Changed`. The canvas uses it only for a creation whose `Inline edit` ends empty (ADR 0062). Distinct from `Selection`, which is also transient view state but isn't tracked here at all.

**Paste anchor**:
The board point a pasted payload's bounding box is centred on — where the user last *indicated*. That is the pointer's board position when the pointer is over the canvas, the press point that opened a `Context menu` for a paste invoked from its row, and the viewport centre otherwise. A menu opened from the keyboard has no press point and takes the viewport centre, deliberately not a press point stored earlier in the session, which names somewhere the user has since navigated away from (ADR 0026). The payload translates as a rigid body relative to it, so internal relative geometry survives, floating ends included. The box centred on the anchor is the payload's extent, instances unioned with every end that resolves, so an edge-only payload has one too; with `Snap-to-grid` on, its top-left lands on the grid. Successive pastes onto an unchanged anchor cascade by +20,+20 board units each; a changed anchor resets the cascade. "Unchanged" is judged on where the paste would land after snapping, so a pointer nudged within one grid cell still cascades rather than stacking a copy exactly on the last one. Pasted plain text becomes a `Text` instance placed by the same rule.

**Duplicate run**:
A sequence of duplicates where each lands at the same offset from the last as the last sits from its own source. Duplicate is `Ctrl+D` or the object menu's Duplicate row; it copies exactly what a copy would carry, lone edges included, onto the board with fresh ids and never touches the clipboard. It exists while the `Selection`, instances and edges together, is exactly what the last duplicate produced, and any selection change ends it, even one that later comes back to the same set. The offset is read from committed bounds when the duplicate is invoked, top-left to top-left of the extent over the selection (instances unioned with every edge end that resolves), so any way of moving the copy counts and no gesture feeds it. The first duplicate in a run offsets by +20,+20 board units. Every offset is replayed as it stands, never snapped, so the nth copy sits exactly n offsets along even off the grid. The copies become the `Selection` at the board's top level, stepping out of an `Entered group` as a paste does, in one history entry; focus stays where it was and no `Inline edit` opens. Transient canvas state, never persisted and never in `History`; replacing the `Board` ends it (ADR 0039).
_Avoid_: remembered offset, which suggests a stored delta from a gesture; conflating it with the `Paste anchor` cascade, which measures from an absolute point.

**Align strip**:
The object menu's one row of glyphs for the six align actions (left, centre, right, top, middle, bottom) and the two distribute actions (horizontally, vertically), a `role="group"` of `menuitem`s named by their `title`, sitting before the four z-order rows. Each glyph runs a public method on the canvas (`OnAlignLeftPressed` through `OnDistributeVerticallyPressed`), so a host can wire its own buttons. They act on the `Selection` unexpanded: an instance or a `Group` is one entity, a group moves as one body with its members' arrangement kept, edges are skipped and count toward nothing, and inside an `Entered group` the entities are the selected direct members. The six align glyphs show at two entities and the distribute pair at three; below that they are hidden, and a call does nothing. Align sets every entity's matching line to the selection box's edge or centre line; under `Snap-to-grid` that one coordinate is rounded to the dominant grid line, so the result stays exact for every action. Distribute orders entities by their centre on the axis and makes every gap equal, measured from the first entity's leading edge to the last entity's trailing edge rather than the selection box, so with snap off neither end moves; under snap the gap rounds to a whole grid step, never below one step when the ideal gap is positive, the first entity stays and the last drifts. An entity that would not move contributes nothing, and an action that moves nothing adds no history entry; otherwise one action is one entry. Up and Down treat the strip as one row and Left and Right move across it. No chords, by design (ADR 0014).
_Avoid_: toolbar, key object, anchor.

**Clone drag**:
A `MoveSelection` with Alt held, where a copy of the selection follows the pointer and the originals stay put. The copies are exactly what duplicate would build, with fresh ids and stacked above everything on the board, groups whole, interior edges carried and every selected edge's end on an uncopied instance floating. They are built on the first move with Alt held, so an Alt-click copies nothing, and kept for the rest of the press, so toggling Alt shows the same copies each time. They sit in the `Gesture preview`'s pending fragment, where live geometry resolves them, and render as committed entities do, mounted whatever windowing says, with no tab stop and no hit region. While they show, the selected look moves from the originals to the copies, selection box included, but the `Selection` itself stays on the originals. The originals are snap candidates and the copies are not, so a copy aligns with its own source. At release the copies are added to `Board` where the preview showed them, in one history entry, become the `Selection` at the board's top level and start a `Duplicate run` whose source is where the originals stand, so `Ctrl+D` straight after repeats the drag's offset. Alt is read live, so the same press can switch between moving and cloning, the switch shows the moment Alt changes, and the release commits whichever was last on screen (ADR 0043). Escape or any cancel drops the copies and leaves the board and the `Selection` as they were. A mode of `MoveSelection`, not a ninth `Pointer gesture` (ADR 0042).
_Avoid_: alt-drag duplicate as a separate gesture; reading it as moving the originals and leaving copies behind, which would carry externally attached edges away from the copies' source.

**Centre resize**:
A `ResizeSelection` with Alt held, where the centre of the selection's instances-only bounding box, read at press, stays fixed and the edge opposite the handle moves in mirror with it, so a driven axis grows by twice the pointer's travel. An edge handle drives one axis and a corner both. Members scale inside the box as on any resize, and the box's minimum size clamps both edges the same distance from the centre. Alt is read live, and every move recomputes from the start box, so on a toggle the opposite edge jumps while the handle stays under the pointer, and a release commits whichever box was last shown. On each driven axis both edges are snap anchors and the smallest correction wins, the other edge moving the same amount the opposite way: object snapping takes an axis where either edge matches, skipping a match below the minimum size, and the grid fills the rest, with the floor applied after a grid snap so a box at its limit may sit off the grid. Guides are drawn for both edges of an object-snapped axis. Nothing marks the mode. A mode of `ResizeSelection`, not a ninth `Pointer gesture` (ADR 0057).
_Avoid_: resize from centre as a separate gesture; conflating it with aspect-lock, which is out of scope and would bind `Shift`.

**Grid**:
The canvas's visual position/scale reference — concurrent layers stepping by 10x spacing, crossfading in and out as zoom crosses each layer's legibility threshold to simulate infinite depth in either zoom direction. Purely a `DiagramCanvas` rendering concern; not part of `Board`, not persisted.

**Snap-to-grid**:
A toggle, on by default, causing placement, move and resize to snap to the currently-dominant `Grid` layer's spacing. Ephemeral view state, like `Selection` — never part of `Board`, never persisted, regardless of the grid layer it currently tracks. A move or placement rounds the top-left of the selection's bounding box and moves the selection as one rigid body. A move rounds inside every frame of the drag, so the snapped position is what the user watches and what the release commits, with no jump. A move never rounds size, so an entity whose size is not a multiple of the step keeps its far edges off-grid. A resize rounds only the edges its handle moves, each to the nearest line that keeps the minimum size, inside every frame like a move; the anchored edges stay where they were, and a multi-selection rounds only its bounding box while members scale exactly inside it. Holding `Ctrl` through a move or resize suppresses it, read live from every move and never at press, so pressing it with the pointer still lets go of the grid at once and releasing it snaps again; the release commits what was last shown. A host turns the toggle off with `SnapToGrid="false"` or through `@bind-SnapToGrid` (ADRs 0011, 0020, 0024, 0043, 0048).

**Object snapping**:
An off-by-default toggle aligning a moved or resized `Selection`'s edges and centres to those of neighbouring entities, drawing an `Alignment guide` along whatever matched. A host binds it with `@bind-ObjectSnapping`, beside `SnapToGrid` and independent of it; it has no chord, and `OnToggleObjectSnappingPressed` flips it and notifies the binding. It resolves **per axis** and beats `Snap-to-grid` on any axis where it fires, leaving grid to fill the other. `Ctrl` suppresses both, and the locked axis of an `Axis lock` gets neither. A move matches the start, centre and end of the selection's bounding box, as one rigid body, against the same three lines of every candidate, nine pairings per axis, plus the `Equal-spacing snap` positions. A resize matches only the edges its handle moves, and skips a match that would take the box below its minimum size. Placement and paste get grid only, since neither has a frame for a guide to live in. Its tolerance is 8 *screen* pixels, because the number states how precisely a human can aim a pointer rather than anything about the board. A match holds until its anchor drifts 1.75 times the tolerance away, so keeping a snap takes less effort than acquiring it. Above 3 screen pixels per millisecond, read from the velocity the listener reports with every move, it stands down and drops what it held; the grid still snaps. A move re-sent for a modifier change carries zero velocity. The search runs twice per move: once to find the offset, then again from the snapped position to collect every line the selection now shares, so the guide shows where the selection is rather than where it was. Candidates are the on-screen instances, `LOD placeholder`s included, minus the selection's own; a guide to something invisible is a line to nowhere. `Group`s are never candidates, since every bounds edge already coincides with a member's and only their centre would be new. `Locked` ones are included, a partly locked group's locked member left behind by a move among them, since snapping is reference rather than participation (ADR 0024).
_Avoid_: smart guides, snap lines — those name the visual, which is the `Alignment guide`.

**Alignment guide**:
The line drawn along a coordinate `Object snapping` matched, spanning the whole viewport rather than stopping at the outermost matched entity. Only the axis object snapping took draws one; a grid-governed axis draws nothing. It is an SVG line in the guide `Paint layer`, in board space, with `vector-effect="non-scaling-stroke"` so its width stays one screen pixel at any zoom. It reads its own `Theme token`, `--d12-alignment-guide`, deliberately never the accent, since a guide only ever appears while a selection is being dragged and would vanish against the selection's own box. Drawn at half intensity precisely because it is full-bleed: a viewport-length line puts far more colour on screen than one bounded by its matches.

**Equal-spacing snap**:
An `Object snapping` match that reproduces a gap already present elsewhere, so a new entity dropped beside a row lands at the row's own rhythm. A gap exists only between two neighbouring entities overlapping on the perpendicular axis, with nothing reaching into the space between them. The candidates are filtered to those overlapping the mover on the perpendicular axis before any pair is formed, so the pairing only runs over the mover's own row. The mover may land after or before any row member at a gap the row already has, or centred between two members with room for it. Its guide is a segment across each matching gap with a cap at each end, the mover's gap drawn with the gaps it repeats, in the same token as an `Alignment guide`. Moves only, never resize: equal spacing is a claim about layout *between* entities and has no obvious meaning while one entity's size is changing.

**Axis lock**:
Holding `Shift` through a move, discarding motion on one axis so the `Selection` travels in a straight line. The axis follows the press-anchored delta and is re-read every move: the axis the pointer has travelled less along from the press is the one held, horizontal motion winning a tie. `Shift` itself is read live, so letting go mid-drag frees the motion and pressing it mid-drag straightens it with the pointer still, since a modifier change re-sends the last pointer position as a move (ADR 0043). A `Shift` press on a non-member still appends it at press, and the drag that follows locks only while `Shift` is held. The locked axis is exempt from all snapping, since rounding it to a grid line would move the selection along the very axis just locked. Moves only: `Shift` stays unbound on resize, where every tool a user has met makes it mean preserve-aspect-ratio (ADR 0024).

**Nudge**:
An arrow-key move of the `Selection`, one `History` entry per press-to-release burst however many repeat keydowns it spans. The step is one screen pixel divided by scale with `Snap-to-grid` off, and the distance to the **next** dominant `Grid` line with it on — next-line rather than plus-one-spacing, so an off-grid entity is repaired on the first press instead of jumping in grid-sized steps that never land. Under snap it measures from the top-left of the selection's bounding box, the point snap-to-grid anchors, and only the arrow's axis moves. `Shift` multiplies by ten: ten screen pixels with snap off, and the tenth line on with it on, which is one cell of the next coarser layer. A nudge pressed while a `Pointer gesture` owns the press does nothing. Never object-snaps: unlike a drag there is no continuous motion to make the pull legible, and the align commands are the keyboard's exact answer (ADR 0026).
_Avoid_: arrow-key move, keyboard nudge — this is the only nudge there is.

**Shortcut hint**:
The chord rendered beside a `Context menu` row, muted and hidden from assistive tech so the row is still named by its label. Shown only while that binding is live, so the Snap to Grid row shows `Ctrl+'` only while the host leaves `EnableSnapToGridShortcut` on, and rows with no chord at all — the align strip, Unlock All, object snapping — show none by design rather than omission. Rendered from one platform boolean the browser reports once, at init, beside the container size, and shared with the pointer path's macOS check: Apple platforms concatenate `⌥⇧⌘` symbols with no separator (`⇧⌘G`), with `⌫` for Delete, everywhere else joins words with `+` (`Ctrl+Shift+G`). Since every chord accepts `Ctrl` or `Cmd`, `Ctrl` is drawn as `⌘` on a Mac. Two conventions, not one string with a modifier substituted (ADR 0026).

**Content extent**:
The smallest `Bounds` enclosing everything on a board — every component instance's committed bounds unioned with every resolvable edge endpoint, since an `Edge` with floating endpoints is content that no component's bounds covers. An endpoint that no longer resolves is skipped rather than read as the origin, and an edge label or an orthogonal route's bow outside its ends is left to the framing margin. Derived on demand from `Board`, never stored, internal to the library, and null for a genuinely empty board. Restricting the same computation to a `Selection`'s instances, a selected group contributing its members, and its edges is what Zoom to Selection frames; paste, duplicate and clone drag measure a fragment with it too.
_Avoid_: board extent — ADR 0011 abolished a fixed board size; this is measured from content, not a configured limit.

**Framing**:
Moving the viewport so a given board rect fills it — the shared operation behind zoom-to-fit, zoom-to-selection and the `Minimap`'s own scale, and the inverse of `ZoomPanTracker.Viewport`. `ZoomPanTracker.Frame(bounds)` is public, so a host reaches it as it reaches `SetPanPosition`. It sets scale and pan together in one change, contain-not-cover, scaled to 0.9 of the full container rect, never magnifying past 1.0, then clamped to the host's zoom limits and centred at whatever scale it got; before the container has been measured it does nothing. Three viewport commands use it: **Zoom to Fit** (`Shift+1`) frames the `Content extent`, **Zoom to Selection** (`Shift+2`) frames the selection's, and **Zoom to 100%** (`Shift+0`) sets scale 1.0 about the container's centre. Each is a public method on the canvas and a context menu row, Fit and 100% on the canvas menu and Selection on the object menu, with its chord as the hint. An empty board and an empty selection are strict no-ops, and Zoom to Selection never falls back to fitting everything. The chords match `event.code`, so they hold on any layout, and act only while focus is inside the canvas container and not in an editable element. Each command is a **framing flight**: the state arrives at once and the content element's transform animates to it over 250ms, so nothing in the model has a notion of time. The listener turns pointer events off on the container from the flight's `transitionrun` to its `transitionend` or `transitioncancel`, never by a timer, so a press mid-flight cannot land on what is about to be under the pointer; a flight that starts while a press is held leaves pointer events on, since the press already owns the pointer. `prefers-reduced-motion` zeroes the duration, which starts no transition and so no guard. The pan that brings a new `Inline edit` into view is a flight too. The next viewport change that is not framing drops the flight's transition. The canvas frames all content once for each new `Board` instance, unanimated, as soon as the container has been measured, and draws no board content before then, so a board never shows first at a view the fit replaces. There is no opt-out; a host that floats chrome over the canvas corrects the view afterwards through the public tracker (ADR 0015, ADR 0033).
_Avoid_: zoom — framing always sets pan as well, and is a discrete destination rather than an increment.

**LOD placeholder**:
The generic stand-in rendered for a component instance once its on-screen size (`Bounds` × current zoom scale) drops below a configurable threshold — swaps out the full Razor component tree for a plain box built from data the registration contract already requires (`DisplayName`/`Icon`), rather than mounting every instance at full cost regardless of how small it renders. Cheap to render, not inert: it is a full `Hit target` with the `instance` role, so a click selects it, a press drags it and a marquee sweeps it like any instance, since the cost it exists to avoid is *mounting*, and a board whose content stopped being selectable when zoomed out would be unusable at exactly the zoom where grabbing a cluster matters most (ADR 0017). Whether an instance is placeholdered is read from its committed `Bounds`, and frozen for the participants of a live `Pointer gesture` until release (ADR 0020). It has no tab stop of its own yet, though ADR 0017 gives it one.
_Avoid_: reading it as non-interactive — ADR 0011 swaps the mounted component tree, never the entity's reachability.

**Hit target**:
What a pointer press resolves to — a `(role, entity, part)` classification produced once, at press, by walking up the DOM from the event's own target to the nearest marked element, carried alongside the press count, `pointerType`, buttons and modifiers. The role is a closed set (`instance`, `resize-handle`, `port`, `edge`, `edge-endpoint`, `edge-label`, `selection-bounds`, `selection-handle`, `author-content`, `canvas`), and `canvas` means the walk found nothing rather than that nothing was there. Resolved in JavaScript because Blazor's `MouseEventArgs` carries no event target, which is why arbitration is otherwise forced out into per-element handlers. The press alone decides everything that must happen synchronously — `preventDefault`, `setPointerCapture`, `Focus transfer`, the `Drag threshold`, and suppressing the browser's native context menu — the role supplying the answers for a classified press and `MinimapPan` taking fixed ones, since it is entered directly and has no role. `author-content` is the one role whose answers additionally depend on *how* it was classified: inferred from a natively-interactive element, the browser's own focus and text selection are left alone; matched by an author's opt-in marker, the target cannot take focus, so the press prevents and transfers like any other (ADR 0036). So JavaScript holds no copy of selection state and reads only what C# has rendered, such as `Locked` or whether an instance is outside the `Entered group` (ADR 0044); choosing the `Pointer gesture` needs the selection and therefore happens in C#, after the hop. Only a *primary* press consumes the role: a secondary or middle press is a `Pan` whatever it hit.
_Avoid_: hit result, pick — "target" is the reference-tool term and the one the classification's own role names describe.

**Hit region**:
The area that resolves to a `Hit target`, expressed as a real element and deliberately not the same shape as what is drawn — an edge's visible stroke is 2 units wide while its region is 20 screen pixels. Where the two differ, the region is the participating element and the visual is painted by a non-participant. Sized against `--d12-scale`, which the canvas content publishes beside its transform, so it stays constant in *screen* pixels at any zoom: an edge's region is a transparent stroke `calc(20px / var(--d12-scale))` wide laid over the line that paints it, and that line takes no presses. Always attached to something visible: a region may exceed its visual, but nothing is hittable with no visual at all — a port span's visual is its dot, a resize span's is the instance's own border. Whether an entity has a region at all is one predicate in C#, read both by the markup that emits the region and by the marquee, so the two cannot drift. Affordance regions on an instance's border are additionally guaranteed **not to intersect**, at any zoom and for any port configuration, which is what the `Border partition` exists to produce and what replaced an earlier precedence rule declaring resize handles the winner over ports (ADR 0028).
_Avoid_: hit box — regions are not all rectangular (an edge's is a stroke).

**Hit stack**:
Every entity at one point on the board, topmost first in paint order, read from the DOM with `elementsFromPoint` rather than computed from `Bounds`. Each entry resolves as a plain press on it would select it, so a grouped member appears as its group unless the `Entered group` or one it was entered from holds it, and duplicates collapse. The selection box and locked entities are left out and edges stay in. The listener sends it with a primary press on the selection box, and with an Alt press on an instance, an edge or a label, and C# reads it for two click outcomes only. A click inside the selection box selects the top entry beneath it, a Shift click toggles that entry, a click over nothing keeps the selection, and a drag from inside the box still moves the selection. Alt+click selects the next entry below the single entity in the `Selection snapshot`, or the entry below the top when the snapshot is not one entry of the stack, wrapping at the bottom; it does so at any press count, so quick Alt clicks keep stepping down, `Shift`+Alt is Alt, `Ctrl`+Alt is a plain click since AltGr arrives as it on Windows, a member selected inside a group the press stepped out of is found as that group, and an entry outside the entered group steps out as a press on it would. With Alt held, a primary press on `author-content` classifies as the instance unless its target is editable or the instance holds a live text selection, so Alt+click reaches beneath an author's control (ADR 0046). A connector drag reads the same DOM stack once more, at release and by role rather than by entity, because a captured release is targeted at the canvas whatever it is over: the topmost port or body of an unlocked component under the pointer decides the drop, chrome, edges and locked components above it are looked through, a port pins the end and anything else leaves it floating. It never decides the `Hit target`.
_Avoid_: z-order list, layer list — those suggest a `ZIndex` sort over the whole `Board`, which ADR 0017 rejected because it can disagree with what the user sees.

**Paint layer**:
One of four fixed stacking contexts inside the canvas content, bottom to top: the edge band (edge lines, the selected-edge halo, edge labels), the instance layer (component instances and `LOD placeholder`s by `ZIndex`, then the host's own content, plus every tab stop), the guide layer (`Alignment guide`s), and selection chrome (marquee, selection box and handles, floating endpoints, connector drag preview). `ZIndex` orders only the inside of the instance layer, so no value can pass beneath an edge or above the selection box. Because edges always paint beneath instances, paint order and the hit order ADR 0017 fixed agree everywhere (ADR 0055).
_Avoid_: reading `ZIndex` as a board-wide z-order — it ranks instances against each other and nothing else.

**Menu verdict**:
Who owns a secondary press on `author-content`: the browser, which shows its own menu, or the canvas, which pans or opens the object menu. Decided once at `pointerdown` by a fixed order (not addressable → canvas; editable target or live text selection → browser; nearest `data-d12-context-menu` marker inside the entity, `browser` or `canvas` → its value; `a[href]`, `video` or `audio` → browser; otherwise canvas), stored, and used up by the press's own `contextmenu` event. Stored rather than re-derived because on Windows `contextmenu` fires at the release point. `<img>` is not inferred, so a built-in Image keeps the object menu. The rules read everything inside an addressable instance's content, not only what classifies as `author-content` for the primary button, so a bare `video`, or an `<img>` carrying the marker, gets the browser's menu while a primary press on it still drags the shape. The marker is the author's way to say whether a right-click in their content is theirs or the canvas's, separate from the `data-d12-author-content` marker, and it never overrides an editable target or a live selection. A browser verdict reaches the canvas as a `Native` press, which captures nothing, prevents nothing and only adds the instance to the selection; a canvas verdict is a `Pan`, as on every other role. A keyboard menu request writes the verdict at its keydown instead, from a capture-phase `window` listener so an author's `stopPropagation` cannot skip it, for the focused element, and the browser's trailing `contextmenu` uses it up without classifying its own target. Outside an instance's content the keydown uses the editable-or-selection rule alone. Every other key and every press anywhere on the page clears the stored verdict before a secondary press on the canvas writes its own, and a repeat keydown neither writes nor clears it. The `contextmenu` listener sits on `window`, because after a menu key with nothing focused the browser's event targets the page body. A `contextmenu` with nothing stored in front of it answers only for the container and classifies its own target as a menu key would, preventing the browser's menu on a canvas verdict without opening one (ADR 0047, ADR 0067).
_Avoid_: native-menu suppression as a separate rule — suppressing the browser menu and opening the object menu are the two halves of one verdict and must not be computed apart.

**Drag threshold**:
The distance a press must travel before it counts as a drag rather than a click — 4 pixels, measured in *screen* pixels so the same physical hand movement crosses it at any zoom. It is what lets one press safely carry two meanings: a `Pointer gesture` releasing from its `pointing` phase runs the click outcome (select, or open the context menu), and crossing the threshold promotes it to `active`. One number for every role and both buttons; JavaScript owns it and does not call C# below it, so any move C# receives is already a real drag. There is deliberately no time-based equivalent: time never promotes a stationary press, however long it is held (ADR 0022). A viewport change under it does, and C# then tells JavaScript to forward every move from that press (ADR 0056).
_Avoid_: treating it as per-gesture tuning — the only dimension it is ever expected to vary by is `pointerType`.

**Focus transfer**:
The single DOM focus move a pointer press makes, to the canvas itself, in the same synchronous window as `preventDefault` and `setPointerCapture`. It exists because preventing the default suppresses the browser's own focus move, and with it the `blur` that commits an inline text edit. One write per press, to one fixed element, whatever the press turns out to mean — a press that changes nothing moves focus exactly as far as a press that changes everything. Focus is never moved because the `Selection` changed; the only other things that move it are the browser's own traversal and a `Command` that names where focus should land, such as `Quick create` handing it to the instance it just made (ADR 0036).
_Avoid_: focus-follows-selection for this — that name belongs to the opposite direction, where landing focus on an entity selects it (ADR 0010).

**Locked**:
An entity's opt-in protection from change — no `Command` modifies a locked `Component instance` or `Edge`, and it takes no part in primary-press hit-testing or marquee selection. `Locked` is a bool on `ComponentInstance` and `Edge`, written only by `ChangeLockedCommand`, persisted as one optional envelope field that is omitted while false, so a board saved without it loads unlocked and serialises byte-identically. C# renders `data-d12-locked` on a locked instance, LOD placeholder, edge hit stroke, edge label and floating endpoint; the listener turns a primary press anywhere inside one into a press on empty canvas, leaves it out of the `Hit stack` and the connector-drop stack, and gives a secondary press on it the canvas's menu, and C# checks the board again on arrival, so `PressToKind` maps a locked primary press to the marquee and a locked secondary press to `Pan`. A *secondary* press is the one pointer route that does reach it, so right-clicking a locked entity selects it and offers the way to unlock it. A locked instance shows no resize handle and no port, is never a drop target, and starts no inline edit; a locked edge is never carried, restyled or labelled, and a port span with one pinned to it pulls a new edge instead. A `Group` holds no flag of its own: locking one is a bulk write across its members and "is this group locked?" is derived from them: a group is locked when every resolving member is, recursively (ADR 0044). The object menu's lock row reads Unlock when every top-level selected entity, edges included, is locked and Lock otherwise, and `Ctrl+Shift+L` does what the row would; the canvas menu's Unlock All, with no chord, unlocks every locked instance and edge in one entry and shows only while something is locked; Delete and Cut show only while their delete would remove something. Select All, the marquee, nudge, Alt+Arrow resize, z-order, delete, props edits and the image rows skip locked entities. An operation on a partly-locked group acts on its unlocked members and leaves the locked ones where they are (ADR 0058): move and nudge carry the unlocked leaves and snap their box, with the locked member left behind as a candidate; resize keeps its handles on the group's real bounds, scales the unlocked members inside and floors the size by them alone, drawing the dragged frame as the selection box mid-resize; align and distribute measure the unlocked box, and a fully locked group counts toward no threshold; delete removes the unlocked members and the group repair follows, leaving the survivors selected. Copying is not modifying: a locked entity can be copied and duplicated, and the copy is locked on every route, the clipboard and `Clone drag` included, while Cut carries only what its delete removes, a copied group left with one member dissolved as the delete's repair would (ADR 0065). A file dropped on a locked empty image makes a new image beside it. Persisted, undoable, and absent by default. Deliberately orthogonal to keyboard reachability — a locked entity stays tab-reachable and appears in the `Property panel` with its fields disabled and an Unlock control live, which is what stops it being locked forever. A lock badge is not drawn yet.
_Avoid_: keying pointer participation and keyboard reachability off one condition — ADR 0017 separates them precisely so locking cannot become an accessibility failure.

**Theme token**:
A named CSS custom property in the shared set that everything the library itself paints reads for its default visual values (surface, border, accent, muted text, …), rather than each element declaring one-off properties. Every canvas-chrome element (`Grid`, `LOD placeholder`, `Palette`, `PropertyPanel`, selection marquee, connector drag-preview, context menu, `Alignment guide`) reads them, and so does library-painted *board content*: an `Edge`, which has no author component behind it and reads `--d12-edge`, the first content-role token, and the built-in component types, whose `--d12-board-*` tokens back a `Themed default` (ADR 0034). Declared independently on each chrome component's own root — not a single global `:root` — so every component works standalone and two canvas instances can carry different themes; a host overriding tokens on a shared ancestor gets one consistent theme across both via ordinary CSS inheritance.
_Avoid_: reading the boundary as chrome versus content — it is **who renders the pixels** (ADR 0016). An author's own component paints its own visual props and the library cannot reach inside, which is what puts them outside the token layer, not the fact that they are content.
_Avoid_: reading every colour literal left in the library as an unowned token. The port-focus and floating-endpoint orange and the white ring on ports and endpoints are fixed signal colours by decision, not theme (ADR 0063).
_Avoid_: citing ADR 0008 as having declined a theming model for instance props. It says nothing about theming; what was declined was a separate style *data model* beside `Props`, which is a different question from what an unset field resolves to (ADR 0034).

**Raised values**:
The token values every surface that floats over the board declares on its own root: `Palette`'s values plus `color-scheme`. `Palette`, the context menu, `PropertyPanel`, the minimap and the property bar declare them. The canvas declares **board values** instead, where `--d12-surface` is the board background and `--d12-border` is the grid-line colour. A floating surface reading board values disappears into the board, which is why the property bar redeclares raised values even though it renders inside `.diagram-container` (ADR 0064).
_Avoid_: reading ADR 0012's "each component declares its own copy" as one value set copied everywhere. There are two copies, and which one a component declares depends on whether it floats over the board.

**Edge colour**:
An `Edge`'s optional own colour, held as board data alongside its routing style and arrowheads. Absent by default, and absence means *no author opinion* rather than a value — it resolves to a `Theme token` at paint time, so an edge nobody has coloured is correct on both themes. An author's colour overrides the token for that edge only, and an empty colour is stored as absent. Arrowheads always match the stroke they end, uncoloured, coloured or selected. `Selection` never repaints an edge: it adds a translucent accent halo under the edge's own stroke, one per selected edge, so a selected edge still shows its colour, width and arrowheads (ADR 0041). A board saved without edge colours loads and saves unchanged.
_Avoid_: treating it as a theme setting — it is per-edge data that persists with the board, and the library makes no legibility guarantee about a value an author chose.

**Themed default**:
A colour property on a built-in component type left `null`, meaning *no author opinion*, and painted from a `Theme token` in that component's own CSS rather than from a stored literal. Applies to `TextProps.Color`, `RectangleProps.FillColor` and `RectangleProps.StrokeColor`, whose old literals were stand-ins filling a constructor slot rather than decisions anyone took. A stored value is an author's choice, taken literally in both themes with no legibility guarantee, so picking a colour is a deliberate opt-out of theming and clearing it is the way back. `StickyNote`'s yellow and its black text are real decisions and stay literals.
_Avoid_: reading it as a mechanism only built-ins get. Nothing in the registration path changes; a component falls back to a token in its own CSS, which any author's component can do against the same public tokens (ADR 0034).
_Avoid_: expecting a registration-time default to be theme-dependent. A `DefaultProps` value freezes into board data at placement, so only *absence* survives to be resolved later.

**Interaction probe**:
A test that drives a real browser and asserts DOM or component state rather than comparing pixels against a committed baseline. It shares a project and the assembly fixtures with the visual tests, runs against a demo page whose board is seeded with fixed entity ids, and has none of their font sensitivity. It reads what C# was handed by recording every call the page's JavaScript makes into a .NET object, asserts a leak by sweeping a buttonless pointer and checking that nothing responded, and fails on any `console.error` the page logs. It exists to reach what only the browser owns: the `Hit target` walk, the `Drag threshold`, the synchronous decisions taken before the interop hop, move coalescing, and the release channels. Its remit is strictly plumbing — that a modifier survived the trip, that a default was prevented, that ten pointer moves in one frame arrive as one call. It never establishes a magnitude, because synthetic input does not reproduce a real device's granularity.
_Avoid_: calling it a visual test — the whole project is named for those, and the distinction is what a failure means: a pixel diff asks a human to look, a probe names a broken invariant.

**Release-reliability case**:
A test that starts one `Pointer gesture`, ends it the way a user plausibly might, then moves the pointer with no button held and asserts nothing responded — a response to a buttonless pointer being the definition of a leaked gesture. One exists per member of the closed set of eight, enumerated by that set rather than written per ticket, so adding a ninth gesture fails the suite until its case exists. A cancel case sits beside it per member, on the same enumeration, since cancellation is where the per-gesture guarantee lives now that no gesture implements any of it (ADR 0031). Blind by construction to `SelectEdge` and `Native`, which are the two members that hold no state and therefore cannot leak.
_Avoid_: asserting the leak by inspecting which gesture is live — there is no observation surface for that, deliberately, and the behavioural form needs none.
