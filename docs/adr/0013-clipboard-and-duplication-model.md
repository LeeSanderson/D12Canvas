# The system clipboard is the only clipboard; a copy carries a closed board fragment, and duplicate never touches it

There is no internal, in-memory clipboard. Copy writes to the system clipboard and paste reads from it, so there is exactly one clipboard and no second copy of the payload that can go stale. The alternative — an internal clipboard consulted in preference to the system one — has a silent correctness hole: copy on the canvas, copy something else in another application, paste back, and an "internal wins" rule pastes content the user has since replaced. No arbitration rule between two clipboards is right in every case, so there is only one.

**The payload is ADR 0004's board envelope verbatim**, exactly as `IBoardSerializer.Serialize` produces it, written as `text/plain`. Copy builds a temporary `Board` holding the copied entities and serializes that; a clipboard payload *is* a board, which is a consequence of ADR 0003's flat, ID-keyed, ownership-tree-free model rather than a coincidence — any subset of a board is self-contained. Paste recognises a payload structurally (it parses as JSON, carries a known `SchemaVersion`, and has a `Components` array) rather than by a marker property, so no new format, no second serializer, and no reimplementation of ADR 0004's two-phase `Props` round-trip is introduced. Pasting the text of a saved board file therefore merges that board in, which is a feature of the choice rather than a hazard of it.

**Clipboard access uses the DOM clipboard events, not the async Clipboard API.** Paste is handled from the `paste` event's `clipboardData`, which requires no permission in any engine, unlike `navigator.clipboard.readText()`. Copy and cut symmetrically use the `copy`/`cut` events, where `setData` runs synchronously inside a user-initiated event with no permission prompt and no transient-activation failure mode. Consequently `Ctrl+C`, `Ctrl+X` and `Ctrl+V` are **not** rows in ADR 0009's keydown shortcut table; they are clipboard-event listeners, and only `Ctrl+D` and `Ctrl+A` are ordinary keydown bindings.

**What travels is the explicit selection, closed over interior edges.** An edge travels only when *both* of its endpoints resolve to component instances inside the copied set, with a selected `Group` expanded to its members recursively. A half-attached edge is dropped rather than carried with its outside end degraded: converting that end to a `FloatingEndpoint` produces a stub that the paste offset moves along with everything else, so it points at nothing in particular, while preserving the outside `ComponentId` silently wires a pasted edge back to the *original* instance within one board, and dangles across boards. Groups travel as `Group` entities, nested groups included. Because `_selectedEdgeId` is an exclusive slot — an edge selection never mixes with an instance selection — a lone selected edge has no interior endpoints and copying it is a no-op that leaves the clipboard untouched, so a previously copied payload survives.

**Every pasted entity gets a fresh GUID**, in the same board or another one. Same-board paste forces this anyway (`Board.AddComponent` throws on a duplicate key), and applying it unconditionally avoids conditional identity whose outcome depends on invisible target-board state. ADR 0003 chose GUID identity precisely so concurrent creation needs no coordination; preserving ids across boards would deliberately create the collision that model avoids by construction. Regeneration must remap five references consistently, not one: `ComponentInstance.Id`; `Group.Id` and every entry of `MemberIds` (which may name nested groups); `Edge.Id`; the `ComponentId` inside both `PortEndpoint` and `CustomPortEndpoint`; and `PortDef.Id` on `CustomPorts`, because `CustomPortEndpoint` references the port's own GUID. `Edge.Label` is a full `ComponentInstance` embedded on the edge with no `Board.Components` entry, and needs a fresh `Id` too, since `Board.FindEdgeLabel` resolves it by id.

**Paste position is the paste anchor**: the pointer's board position when the pointer is over the canvas, and the viewport centre otherwise. A pointer-free path is required regardless, because ADR 0010's keyboard-accessible model means a keyboard-only user has no pointer at all, and viewport centre is already ADR 0009's convention for where new content lands. The payload translates as a rigid body — one delta computed from its own bounding box — so all internal relative geometry survives, including `FloatingEndpoint` coordinates. Successive pastes onto an **unchanged** anchor cascade by `+20, +20`, and a changed anchor resets the cascade; stating the rule over the anchor rather than the input device covers the pointer and keyboard paths with one sentence, and prevents the invisible-pile failure that ADR 0009's click-to-add cascade already exists to prevent.

**Duplicate is a direct board operation that never touches the clipboard.** Implementing it as copy-then-paste would clobber whatever the user has on their real system clipboard as a side effect of duplicating a shape, which follows directly from there being only one clipboard. It offsets by the same `+20, +20`, so one constant serves click-to-add, the repeat-paste cascade, and duplicate alike.

**Select-all selects top-level entities**: every component instance in no group, plus every outermost `Group`. Selecting every component instance individually would place grouped members directly into the selection set and break the invariant `EffectiveSelectionId` maintains for both click and marquee, under which a selection only ever holds top-level ids. Edges cannot participate — `_selectedEdgeId` is a single exclusive slot — so select-all excludes them, and select-all followed by delete does not clear a board. That limitation is recorded as a known consequence here rather than fixed, because widening edges into the general selection set amends ADR 0006's selection model and belongs with the arbitration and hit-test work.

**No new command type is needed.** Paste and duplicate are each one `CompositeCommand` wrapping `AddEntityCommand` per instance, `GroupCommand` per group, and `AddEdgeCommand` per edge — exactly the composition ADR 0007 anticipated for a multi-entity gesture. Cut is the clipboard write plus the identical composite `OnDeletePressed` already builds, as one history entry; undoing a cut restores the entities and deliberately does not un-write the system clipboard, which is not the application's to revert. Cut on a lone selected edge is a no-op rather than a delete, since copy is a no-op there and cut must never destroy content it did not first capture. Copy with an empty selection does not `preventDefault`, so the browser's own copy of selected page text runs normally.

**Paste and duplicate select what they produced**, replacing the prior selection, so a duplicate can be dragged immediately. Selection stays entirely out of history per ADR 0006 and 0007; instead, **a selection id that no longer resolves to a live entity is dropped when the selection is read.** That keeps undo's existing "selection is untouched" rule intact while removing the selection chrome that would otherwise hover over nothing after an undone paste, and it fixes the mirror case — an undone delete — at the same time.

**Foreign clipboard content is accepted for two cases.** Plain text becomes a `"text"` component instance and a bitmap becomes an `"image"` instance, both landing at the paste anchor under the same position, history and selection rules as a board payload. Both types are always available, since `BuiltInComponents.RegisterAll` is called unconditionally from `AddD12Canvas`. Where a pasted image's bytes are *stored* is deliberately not decided here — inlining them as `data:` URIs inflates the board, the persisted envelope, and ADR 0007's history buffer, which holds entity references until eviction — and is owned by the separate asset-storage decision that reopens ADR 0004.

**A payload naming an unresolvable `ComponentTypeKey` pastes partially.** Paste uses ADR 0004's partial deserialize path rather than the strict one, then re-applies the interior rule against what actually materialised — dropping edges that lost an endpoint and pruning `MemberIds` for members that did not survive. One unknown type in a large payload therefore costs that one entity rather than the whole paste. Warnings surface on a host-subscribable event, in the shape of the existing `SelectionChanged`/`Changed` events, since the library ships no notification chrome of its own.

**The five bindings are `Ctrl+C`, `Ctrl+X`, `Ctrl+V`, `Ctrl+D` and `Ctrl+A`** (with `metaKey` accepted alongside `ctrlKey`, as every existing binding already does), colliding with nothing in ADR 0009's table, ADR 0011's `Ctrl+'`, or ADR 0010's set. `Ctrl+D` and `Ctrl+A` call `preventDefault` against the browser's bookmark and select-all-text defaults. All five are guarded by `isEditableTarget` **and** by focus being within the canvas container — a stricter rule than the existing rows carry, because `isEditableTarget` alone does not protect a host page's user selecting a paragraph of its own text and pressing `Ctrl+C`. ADR 0010's tab stops and the existing click-driven focus round-trip already place focus inside the canvas whenever anything is selected, so the stricter guard costs nothing on the normal path. No host opt-out parameter is added; the focus rule is the whole guard.

**Considered and rejected:**
- **An internal in-memory clipboard**, alone or alongside the system one — rejected for the staleness hole above, and because an internal-only clipboard makes `Ctrl+V` ignore the user's real clipboard, which reads as broken.
- **A narrower clipboard-only format** — would reimplement the two-phase `Props` round-trip, the one part of ADR 0004 genuinely hard to get right, for a smaller payload nobody measured.
- **A discriminating marker property** on the payload (Excalidraw's `excalidraw/clipboard`, tldraw's `application/tldraw`) — rejected because those tools' clipboard payloads carry app state their file format does not, while D12Canvas's would be byte-identical to a board file; structural recognition costs nothing and makes pasting a saved board work.
- **`navigator.clipboard.readText()` as the read path** — drags in permission prompts and per-engine divergence that the `paste` event does not have.
- **Carrying half-attached edges**, either floating or with the outside `ComponentId` preserved — both produce results the user did not ask for, detailed above.
- **Preserving entity ids when the target board has no collision** — makes identity depend on invisible state and puts one GUID in two boards.
- **Always pasting at the viewport centre** (reusing ADR 0009's click-to-add convention verbatim) — simpler and pointer-free, but ignores where the user is pointing, which reads as indirect on a direct-manipulation surface.
- **Pasting in place at the original coordinates** — the right answer for moving content between boards, but a same-board paste lands exactly on top of its source and is invisible, and ADR 0011's unbounded extent means a cross-board paste frequently lands off-screen.
- **Remembered-offset duplicate chaining** (tldraw replays the last Alt-drag clone's offset on each `Ctrl+D`; Figma continues the same distance) — clearly the better interaction, but it depends on a reliable "a move gesture just committed, by this delta" signal that does not currently exist, and deciding it now would spec ahead of the arbitration and live-geometry decisions. Recorded as open rather than closed.
- **Selecting every component instance on select-all**, flattening groups — breaks the top-level-ids invariant every other selection path maintains.
- **Widening `_selectedEdgeId` into the general selection set** so select-all could include edges — a real defect, but amending ADR 0006's selection model from the clipboard decision would pre-empt the arbitration work that owns it.
- **Undo clearing the selection** — would remove phantom chrome without a pruning rule, but changes undo's behaviour for every gesture, so undoing a nudge or a prop edit would also drop the selection.
- **A strict deserialize on paste** — one unknown type would discard an entire payload.
- **Ignoring all foreign clipboard content** — smallest surface, but pasting text onto a whiteboard doing nothing reads as broken.
- **A host opt-out parameter** in the shape of ADR 0011's `EnableSnapToGridShortcut` — rejected as redundant once clipboard handling requires canvas focus, which already leaves the host's own bindings intact everywhere outside the canvas.
